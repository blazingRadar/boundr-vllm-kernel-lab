## What Actually Changed

This is a backend-path bugfix, not a brand new GPU kernel.

The important fix is in `quark_moe.py`:
- `_AITER_NATIVE_OCP_MX_SCHEMES` changed from:
  - `("w_mxfp4",)`
- to:
  - `("w_mxfp4", "w_mxfp4_a_mxfp4")`

That means the mixed MXFP4 activation + MXFP4 weight MoE path was previously treated as unsupported and pushed into emulation, even on supported hardware.

The matching update in `rocm_aiter_fused_moe.py` clarifies that:
- `mxfp4` variants use `BLOCK_1X32`
- unsupported `mxfp6` / `mxfp8` paths continue to use emulation

## Read

This commit strongly supports the thesis that one major AMD gap surface is wrong backend selection, not only raw kernel weakness.

If a supported W4A4 MoE path silently falls into emulation, the performance loss can be massive without any change to model architecture or hardware.
