## What Actually Changed

This commit does three important things:

1. It adds a tuned GEMM gate:
- `rocm_aiter_ops.is_tgemm_enabled()`
- gated on AITER linear support and `gfx950`

2. It adds a new unquantized GEMM path in `layers/utils.py`:
- after skinny GEMM checks
- before falling back to `torch.nn.functional.linear`
- route:
  - `from aiter.tuned_gemm import tgemm`
  - `return tgemm.mm(x, weight, bias)`

3. It effectively disables the earlier DeepSeek-family dynamic MXFP4 auto-enable policy in `quark.py`:
- removes `maybe_update_config(...)`
- leaves:
  - `self.dynamic_mxfp4_quant = False`
- comment says the overhead of dynamic MXFP4 quantization negated the expected gains

## Read

This is not a pure kernel invention commit. It is path-policy correction.

The strongest signal is:
- dynamic MXFP4 for these attention projection layers was not paying off
- tuned unquantized GEMMs were worth exposing through AITER instead

That means the performance frontier here is partly:
- quantization overhead versus compute savings
- exact layer shape behavior
- model-family-specific path policy

## Likely Performance Surface

- attention projection layers
- dynamic quant overhead
- tuned BF16/FP16 GEMM selection
- AITER `tgemm` path on supported ROCm hardware

## External Dependency Signal

This commit clearly depends on real AITER substrate:
- `aiter.tuned_gemm`

That means some future optimization work may belong more in:

## Research Value

Very high.

This is the best evidence so far that the real opportunity is:
- trace which path executed
- separate “quantized” from “faster”
- understand when tuned unquantized GEMM beats dynamic FP4 quant

## Suggested Benchmark

On `gfx950`:
- compare AITER `tgemm` enabled vs disabled
- compare dynamic MXFP4 path on vs off
- isolate attention projection layer throughput and end-to-end token throughput

## Suggested Trace Question

When `tgemm` is enabled, do the hottest kernels move from generic linear/fallback paths into AITER tuned GEMM calls, and does TTFT or decode latency improve materially?
