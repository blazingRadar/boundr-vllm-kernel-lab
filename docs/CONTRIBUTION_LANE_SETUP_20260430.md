# Contribution Lane Setup

## What The Lab Can Realistically Do

1. learn the stack vocabulary
2. learn route and fallback behavior
3. audit tuned coverage
4. identify a small public contribution surface
5. produce a reviewable packet

## What The Lab Should Not Pretend Yet

1. that it is ready to out-design AMD's kernel team
2. that a large low-level kernel PR is the best first move
3. that one benchmark means ecosystem mastery

## Immediate Lane Definition

Near-term contribution lane:
- diagnostics
- route fixes
- shape coverage analysis
- benchmark and trace discipline

Only after those:
- kernel-adjacent performance changes
- possible low-level kernel work

## Success Condition

The first success is not:
- "we invented a new kernel"

The first success is:
- "we produced a small, technically correct change or tool that an AMD reviewer would take seriously"
